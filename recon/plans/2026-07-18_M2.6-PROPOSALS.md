#### [M2.6-EXT-10]

> **tags** · m2.6, system
> **tl;dr** · M2.6-EXT-10 — M2.6 system.
> **ctx** · M2.6-EXT-10 — M2.6.
> **meta** · depends-on: — · depended-by: -

##### Systems Touched
Hardens the base "Sector Boundary Entity Handoff" Implementation Step above into a full two-phase commit, over the M2 EventBus (`entt::dispatcher`), keyed on `StableId` (not raw `entt::entity`), against the sector streaming/ownership state this milestone defines.

##### Math
State machine per in-flight handoff, advanced by acknowledgment events with a wall-clock timeout guard:

`state ∈ { Idle, Requested, Acknowledged, Committed }`

`state → Requested` on boundary crossing; `Requested → Acknowledged` on target ack; `Acknowledged → Committed` on target commit-confirm; `Committed → (cleanup) → Idle` after source release.

`Timeout ⟺ (now − t_phaseEntered) > τ_ack` → roll the transfer back to `Idle`, source retains ownership.

##### Algorithm
The base Implementation Step already specifies a two-phase *handshake* (request → ack, source keeps simulating until acknowledged). This EXT hardens that into a full **two-phase commit** with an explicit cleanup phase and timeout handling for lost acks — because a bare request→ack pair has no defined behavior when the ack (or the entity's constituent state) is dropped by a target sector that started streaming out mid-handoff, which on a bitmask-only check silently leaves the entity either double-owned or un-owned.

The four phases:

1. **Request.** On boundary crossing the source sector dispatches `EntityHandoffRequested { StableId, sourceSector, targetSector, seq }` and moves that handoff to `Requested`. The source **keeps simulating** the entity (fail-safe, per the base step).
2. **Ack.** The target sector, only once it has streamed in and reserved a slot, replies `EntityHandoffAcknowledged { StableId, seq }`. Source moves to `Acknowledged`. If the target cannot accept (still streaming, budget-starved) it either stays silent (handled by timeout) or sends an explicit `EntityHandoffRejected` that rolls the source straight back to `Idle`.
3. **Commit.** The source transfers the authoritative entity state (dvec3 `Transform`, physics velocity, AI state) and dispatches `EntityHandoffCommit { StableId, seq }`; the target confirms it now owns and is simulating the entity. Only now does the source stop simulating.
4. **Cleanup.** The source releases its now-dormant proxy of the entity and clears the handoff record; the target clears its pending-reservation flag. Both ends return to `Idle`.

Every phase is guarded by `τ_ack`: if the expected event for the current phase doesn't arrive within the timeout, the transfer **rolls back** — the source, which never relinquished simulation until the Commit phase, simply resumes full ownership and re-arms the handoff on the next crossing tick. This makes a lost ack fail *safe* (a brief ownership straddle, never a lost entity), consistent with the base step's stated fail-safe-not-fail-open guarantee, and the whole exchange rides the same `WorldOriginRebased`-aware EventBus so an origin rebase mid-handoff is applied identically on both sectors. The `seq` counter rejects a stale ack from a previous, timed-out attempt.

```cpp
// Per-entity handoff record advanced by EventBus acks with a per-phase timeout rollback.
// Source keeps simulating until Commit; a lost ack rolls back to Idle (fail-safe, never entity-loss).
enum class HandoffPhase : uint8_t { Idle, Requested, Acknowledged, Committed };
struct SectorHandoff {
    uint64_t stableId{0};
    uint32_t targetSector{0};
    uint32_t seq{0};
    HandoffPhase phase{HandoffPhase::Idle};
    double phaseEnteredTime{0.0};
};
// Called each tick per active handoff; returns true if the transfer should roll back this tick.
inline bool TickHandoffTimeout(SectorHandoff& h, double now, double tauAck) {
    if (h.phase == HandoffPhase::Idle || h.phase == HandoffPhase::Committed) return false;
    if (now - h.phaseEnteredTime > tauAck) {
        h.phase = HandoffPhase::Idle; // source (still simulating) resumes full ownership
        h.seq++;                      // invalidate any late ack from the timed-out attempt
        return true;
    }
    return false;
}
```

**How It Works:** While anchored to a moving platform (vehicle bed, collapsing floor section), the character's position is tracked as a local double-precision offset from the platform's root transform rather than in absolute world space, then converted to camera-relative single precision only at the final draw step. void ApplyFloodBuoyancy(CharacterPhysiologyComponent& phys, float waterDepthAtFeet, float dt) {
```cpp
    if (waterDepthAtFeet <= 0.0f) return;
    constexpr float rhoWater = 1000.0f, g = 9.81f;
    float submerged = std::clamp(waterDepthAtFeet / phys.waistHeightM, 0.0f, 1.0f);
    float buoyancyAccel = (rhoWater * phys.capsuleVolumeM3 * submerged * g) / phys.massKg;
    phys.kinematicVelocityInput.y += buoyancyAccel * dt; // fed straight into ExtendedUpdate()'s velocity input
}
```

## Addendum — self-verify tooling (M2.6 Phase 2, 2026-07-12)

To verify the debug fly-camera without a live display (and to unblock headless
self-verification of input/mouse fixes), two flags were added, scoped identically
to the existing `flyCamera` cvar:

- `--script-input <file>`: drives `Input::poll()` from a tiny text script instead of
  SDL. Format: `K <W|A|S|D|scancode> <f0> <f1>` = hold key frames [f0,f1];
  `M <dx> <dy> <f0> <f1>` = apply mouse delta (dx,dy) each frame in [f0,f1].
  `poll()` replays one `ScriptFrame` per call; key release is emitted at `f1+1` so the
  key stays held across the whole range. Key state persists across frames (matches SDL
  held-key semantics). No new serialization format — distinct from `replay.bin`.
- `--dump-state <file>`: emits the `FlyCamera` pose (frame index, dvec3 position,
  dvec3 forward) as one JSON object per frame. The fly-camera *update* + state-dump run
  in both headless and windowed; only the render injection (`setDevView`) and
  `SDL_SetWindowRelativeMouseMode` are windowed-gated, since headless has no swapchain
  or window.

This makes "does W move / does mouse-look rotate" machine-checkable from a headless run,
removing the dependency on a human at a GPU for that class of regression. Yaw *direction*
(screen-right = mouse-right) and far-cube *steadiness at 50km* still require the human
GPU pass — the tooling proves motion occurs and is dt-correct, not that the sign is
visually correct or that sub-pixel precision holds at range.
