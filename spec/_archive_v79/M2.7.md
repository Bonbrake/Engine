## M2.7 — Combat systems including melee parry, firearms, damage resolution, and limb hit pipelines

> **M2.7 authoring plan.** This stub replaces placeholder authoring with executable systems: limb hit resolution, parry/frame window, firearm ballistics, zombie melee FSM, and minimal-authored voice hit reactions.

### Cluster A: Damage Resolution

#### [M2.7-EXT-01] Limb Hit Component + Bone Mapping
**tags:** damage, limbs
**ctx:** Add a per-entity limb mapping that binds surface hit results to canonical bone slots: head, torso, left arm, right arm, left leg, right leg.
**math:** `limbMask = rayResult.boneIndex → bitset(6)`; each slot carries `health_, maxHealth_, fractureThreshold_`.
**algorithm:** On hit, convert collision contact to nearest bone via capsule/sphere heuristic; write `DamageEvent{limbMask, impulse, direction}`.
**examples:** Headshot with crossbow → `limbMask = 000001`; leg sweep with bat → `limbMask = 100000`.
**failure modes:** Bone lookup misses on procedural mesh → fallback to torso.
**player-facing impact:** Shot placement matters. A leg hit slows zombies; a headshot drops them instantly.

#### [M2.7-EXT-02] Damage Type Enum + Material Response Table
**tags:** damage, materials
**ctx:** Map weapon/damage type against surface material to produce `finalDamage`, `armorPenetration`, `fractureChance`, `bleedRate`.
**math:** `finalDamage = baseDamage * materialMultiplier * armorFactor`; `armorFactor = clamp(1 - armorRating / (armorRating + penetration), 0, 1)`.
**algorithm:** Author a compact `DamageResponseTable` keyed by `{damageType, materialTag}`; values are scalars plus optional flag set (ignoresArmor, causesBleed, breaksBone).
**examples:** Knife vs. leather jacket = low damage, high bleed; rifle vs. concrete = no damage.
**player-facing impact:** Players read material cues and choose tools accordingly.

#### [M2.7-EXT-03] Bleed / Infection / Pain State Machine
**tags:** damage, survival
**ctx:** Convert damage outcomes into survival-status deltas driven by M0/M2 survival stats.
**math:** `bleedRate = max(0, damage - fortitude) * bleedScale`; `pain = accumulatedDamage / painThreshold`.
**algorithm:** Every tick, `health -= bleedRate * dt`, `staminaRegen *= (1 - pain)`, `infectionChance += bodySiteFactor * woundAge`.
**player-facing impact:** A bad encounter produces cascading stat loss; bandages stop bleed but not infection.

#### [M2.7-EXT-04] Parry Frame Window + Directional Guard
**tags:** combat, parry
**ctx:** Melee parry is a 6-frame success window centered on the first contact frame for a blocking input.
**math:** `parryScore = clamp((inputTime - attackStartTime) / parryWindow, -1, 1)`; success if `|parryScore| < 0.5`.
**algorithm:** Author directional guard angles: high, mid, low. Successful parry reflects `reflectedDamage = attacker.force * parryEfficiency`; failure stuns defender for `stunFrames = attacker.force / defender.staggerResist`.
**player-facing impact:** Rhythm matters; spam-block gets punished; well-timed parry turns enemy force against them.

#### [M2.7-EXT-05] Firearm Ballistics: Drag + Drop + Penetration Depth
**tags:** combat, ballistics
**ctx:** Bullet trajectory includes atmospheric drag, gravity, and material penetration.
**math:** `v(t) = v0 - drag * v^2 * dt - g * dt`; `penetrationDepth = (mass * velocity^2) / (materialHardness * crossSection)`.
**algorithm:** ray-marches bullet path in 1m steps; each material hit reduces remaining penetration depth; exits with remaining kinetic energy.
**player-facing impact:** Engagement range matters. Heavy calibers punch through cover; CQB rounds dump energy fast.

### Cluster B: Zombie Locomotion and Animation Grammar

#### [M2.7-EXT-21] Zombie Locomotion State Grammar
**tags:** animation, zombie, locomotion
**ctx:** Replace state-machine animation with a procedural motion grammar seeded by authored motion primitives and driven by simulation state.
**math:** `stateScore = w_infection*infection + w_limbDamage*limbDamage + w_terrain*slope + w_targetDist*distanceToTarget`.
**algorithm:** Evaluate state score each tick; if `crawl > threshold` switch to crawl primitive; if `sprint > threshold` switch to sprint primitive; else lurch. Blend over 150ms with authored transition mask.
**player-facing impact:** Zombie motion reads semantically: fresh ones sprint, wounded ones drag themselves, limbless ones shamble. Players learn threat grammar without reading a health bar.

#### [M2.7-EXT-22] Procedural Reach / Grab Over IK
**tags:** animation, IK, zombie
**ctx:** Generate reach arcs procedurally from target position + zombie arm length; no authored “grab” animation per subtype.
**math:** `reach = baseArmReach + reachBias * (targetShoulder - headPosition).length()`; `grabSuccess = reach > distance && inCone`.
**algorithm:** Sample target shoulder/frame-space position; drive IK target; if within cone and range, trigger grab event.
**player-facing impact:** Zombies realistically stretch for windowsills and over barricades without artist-authored per-scene content.

#### [M2.7-EXT-23] Feign-Death Trigger + Ragdoll Twitch
**tags:** animation, zombie
**ctx:** Some zombies enter “last breath” procedural state instead of immediate death.
**math:** `feignChance = baseFeignChance * (1 - damage/lethal) * personalityFactor`.
**algorithm:** On lethal hit, roll feign chance. If yes, transition to ragdoll with periodic muscle-twitch driven by noise function `twitch = sin(t * freq) * decay`; player proximity restarts twitch amplitude.
**player-facing impact:** Players learn not to trust corpses, creating tension without authored scares.

#### [M2.7-EXT-24] Parkour Vault / Climb Input-to-Motion Mapping
**tags:** animation, human, parkour
**ctx:** Map human movement input + surface normal + step height to procedural parkour motion.
**math:** `vaultSelection = argmin_{primitive} distance(inputVelocity, primitive.requiredVelocity)`; primitive options: step, vault, climb, drop.
**algorithm:** Query surface normal + hip clearance + ledge depth; pick matching primitive from authored motion seed database; blend into runtime pose.
**player-facing impact:** Human traversal feels responsive and context-correct; vaults over low walls, climbs through windows, drops from roofs without authored cinematics.

### Cluster C: Minimal-Authored-Voice Hit Reactions

#### [M2.7-EXT-31] Hit Reaction Voice Intent Table
**tags:** voice, combat
**ctx:** Small set of authored hit reaction lines routed through intent/emotion voice director instead of full authored bark tree.
**math:** `intent = argmax(score_alert, score_pain, score_fear, score_rage)` based on `damageTaken, remainingHealth, infectionStage`.
**algorithm:** Each zombie/human selects one categorized line from minimal authored set; voice director applies prosody: pitch, rate, jitter, SPL based on distance, occlusion, material diffraction.
**player-facing impact:** 8 authored lines read as hundreds of distinct reactions because prosody response changes per context.

#### [M2.7-EXT-32] Procedural Vocalization for Aberrant Zombies
**tags:** voice, zombie, audio
**ctx:** Aberrant/mutant zombie vocalizations are synthesized, not authored. Formant tables map body-morphological parameters to spectral filters.
**math:** `formantShift = baseFormant * (1 + bodyMorphology.spectralTilt)`; `snarl = FM(pitchTrack, formantShift, modulationIndex)`.
**algorithm:** Drive frequency modulation from zombie type; convolve with authored noise texture; route through M6 audio propagation for spatial positioning.
**player-facing impact:** Every aberrant zombie sounds distinct without authored VO assets; audio reads threat type before visual identification.

#### [M2.7-EXT-33] Procedural Footfall Audio by Limb Integrity
**tags:** audio, combat
**ctx:** Footstep audio changes as zombie limbs degrade.
**math:** `footfallSPL = κ * mass * |vFoot|^2 * Z_surface` from M6 spec; `limpBias = (1 - legIntegrity) * limpAmplitude`.
**algorithm:** Per-zombie footfall cache; if leg integrity below threshold, substitute limp audio variant with altered cadence.
**player-facing impact:** Player hears threat degradation: a fresh zombie thuds heavily; a wounded one drags and scrapes.

#### [M2.7-EXT-34] Impact Decal + Wound Atlas Runtime Selection
**tags:** combat, visual
**ctx:** One authored wound decal atlas selects runtime decals based on hit location + damage type.
**math:** `atlasUV = baseUV + (damageType * atlasTileSize) + (limb * atlasTileSize * damageTypeCount)`.
**algorithm:** Pool runtime decal projections; reuse handles across zombies; fade after configurable lifetime.
**player-facing impact:** Visual feedback reads clearly: blunts bruise, blades slash, bullets punch through.
