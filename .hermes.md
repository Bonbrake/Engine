## Spec navigation (load lean — context is a finite resource)
1. Start at `spec/llms.txt` — canonical index (per-milestone file list + EXT-block counts).
2. Read `spec/AGENTS.md` for the file map. Open ONLY the one milestone file you need.
3. Each `#### [ID]` block is self-contained (Systems Touched / Math / How It Works /
   Reference Implementation / Player-Facing Impact) with `> **tl;dr**`, `> **tags**`,
   `> **meta**` (depends-on/depended-by) and `> **ctx**` lines, plus an HTML anchor
   `<a id="Mx-EXT-NN">` for deep-linking.
4. `spec/Mx.index.json` sidecars give O(1) `id → {title, tags, tldr, depends_on,
   depended_by, line, anchor}` lookups — load instead of the .md when only metadata is needed.
5. Keep context lean: read the block you need, not the whole milestone, not the whole corpus.

## Editing rules (keep it agent-readable)
- Every EXT block header is `#### [ID] Title` (H4). Do not mix in `## [ID]`.
- Keep the 5-subsection skeleton in order. Keep blocks self-contained (explicit
  `[Mx-EXT-NN]` cross-refs, no "the method mentioned earlier").
- Keep IDs in ascending numeric order within a milestone. Lay `### Cluster A/B/C/D` dividers.
- Strip process noise: `*(RECONSTRUCTED FROM CITATION CONTEXT — VERIFY)*`, `*(gap-file ref: …)*`.
- After ANY structural edit, run a mechanical verifier (real line evidence): 0 duplicate defs,
  0 dangling refs, 0 orphan bodies, code fences balanced. Do not declare done on a thrown
  script or a summary.
- **Milestone spec files (`spec/Mx.md`, `APPENDIX_*.md`, `APPENDICES.md`) are READ-ONLY to the
  agent** except inside explicitly-approved plan batches. Everything else (scripts, tooling,
  `llms.txt`, `*.json` sidecars, `AGENTS.md`, this file) is autonomous.

## Specificity protocol — non-negotiable, applies to every milestone
- **Every number in the milestone docs is authoritative, not a suggestion.** Don't round,
  don't "improve," don't substitute a library default instead.
- **"Propose, confirm" means stop, not proceed-with-a-default.** Every "Decisions to flag"
  line is a hard checkpoint — surface it and wait.
- **API surfaces get verified, not recalled.** Check the actual signature against installed
  package headers (vcpkg) before calling anything.
- **Missing context is a stop condition, not a fill-in-the-blank.** If a file doesn't specify
  something needed, stop and ask rather than inventing an interface.
- **When in doubt about scope, under-scope and flag it.** Don't silently expand a task to
  "while I'm in here" adjacent files.
- **Ground constants in reality, not the code's own structure.** Hardcoded physical/physiological
  constants get cross-checked against real-world reference data (v77 lesson: impulse, infiltration
  rates, cook-off temps were all off by orders of magnitude until verified). Cite the source.

## Repo hygiene — read before touching git
- **Never stage or commit `build/` or `vcpkg_installed/`.** Confirm `.gitignore` covers both.
  If a commit ever includes either path, stop and unstage — don't "fix it in a follow-up commit."
- **Confirm the active branch before writing anything.** State the branch name back at the start
  of a session. Never assume `main`/the last-used branch is still checked out.
- **Touch only files the current milestone's Implementation Steps or EXT items name.** If a fix
  genuinely requires an out-of-scope file, stop and flag it as a cross-cutting change.
- **Never reconstruct file content from another branch's history to "fill in" a gap.** If a file's
  current content is unclear or seems wrong, say so and ask — don't fabricate plausible source.
- **`STATUS.md` / `CHANGELOG.md` are the durable, session-independent source of truth.** Read
  `STATUS.md` first on a fresh session; update it before ending a session that changed milestone state.
- **Dependency versions are locked in `vcpkg.json`.** Don't bump a version to "latest" without an
  explicit milestone item.
- **No duplicate code definitions.** When the same routine appears in a milestone body and an
  appendix, the appendix becomes a cross-reference stub — never a second full copy that can drift
  (v75 lesson: six silent regressions traced to re-embedded code).

## Verification gate (reading is not verification)
- After a change, **actually run the build / verifier** — reasoning that it should work is not
  proof. The spec verifier is `scripts/verify_m0_parity.py`; block counts and anchors must be clean.
- Minimum viable failure-mode handling: `VK_ERROR_DEVICE_LOST` and out-of-memory log the failure
  and exit cleanly — never a silent hang or unguarded crash with no artifact.

## Tooling & developer iteration loop
- Debug-draw is a first-class system (M1) — used, not bypassed with printf-debugging.
- Render graph / pass dependency management is owned by M1; don't hand-roll a second barrier path.
- **Two job systems, not four.** Jolt's `JobSystemThreadPool` (M2) is physics-only. Everything else
  uses the one general-purpose scheduler (enkiTS) at M0. No third scheduler.
- Shader toolchain: HLSL + DXC → SPIR-V. No GLSL-via-glslang side path.
- Pipeline cache persists to disk (M0) — don't rebuild from scratch every boot.
- Profiler of record: Tracy. Confirm RenderDoc-capturable at M0; don't regress it.
- Unit tests for pure-logic systems: Catch2 or doctest, vendored via vcpkg.

## Target hardware — budgets are against this, not the dev machine
**Recommended (dev reference):** RTX 2070 Super, Ryzen 5700G, 16GB RAM — Tier-1/Tier-2 at 60 FPS.
**Floor (Tier-0):** RTX 2000-series (RTX 2060, 6GB VRAM binding case), RX 6000-series (RX 6600, 8GB),
or Arc A580 (8GB). **6GB VRAM is the tightest constraint** every Tier-0 budget is built against.
CPU floor: 6-core/12-thread (Ryzen 5 3600 / i5-10400). **Floor target: 30 FPS (33.3ms/frame).**
Features not universally supported gate behind a capability check with a Tier-0 fallback.

## Performance & resource budgets (Tier-0 floor, 33.3ms/frame)
- Render ~14.0ms · Physics ~5.0ms · AI ~5.0ms · Animation ~3.0ms · Audio ~1.0ms · Headroom ~5.3ms
- Memory: ~4.0GB VRAM baseline (single-viewport) / ~3.3GB (split-screen) on 6GB floor. 12GB system RAM.
  Design-time estimates — verify against real Tier-0 hardware once the render path exists.
- Numerical method budget (coarse rate is intentional, don't upgrade without a stated reason):
  Scent/Fear diffusion (M5.3/M5.4) coarse 2D grid every 3–6 ticks; SEIR (M8) per-region per in-game
  hour; Faction ODEs (M8.5) per-faction scalars per hour; Settlement truss (M8.6) event-driven;
  Groundwater PDE (M10) shared heightmap every 6 ticks.

## Design pillars (priority order)
1. Procedural variety over authored content. 2. One system fed from many places, not one per feature.
3. Cost scales with what's near/visible. 4. Best-looking-for-the-cost, not maximal.
5. Reuse proven defaults for non-focus infrastructure. 6. Tier your ambition, don't assume it.

## ID scheme
Every extended system is `[Mx-EXT-nn]` — stable, load-bearing IDs. Reference by ID, not description.
A numbering gap (e.g. M0 has no `EXT-13`) is an intentional retired ID, not a missing system to invent.

Total scope: 627 EXT design blocks across milestone + appendix files (post Phase 7.6 merge).
Vulkan 1.4 + 100% procedural + modding engine. Historical changelog lives in `spec/00_PROTOCOL.md`.
